1 Mesh Overview
This demo runs on OpenShift Service Mesh 3 in ambient mode. A per-node ztunnel proxy handles L4 mTLS, and optional waypoint proxies provide L7 policy. Enrollment is a namespace label.
How traffic flows through the stack

OVN-Kubernetes (cluster CNI)
OVS bridge per node, veth pairs into pods
Same-node: L2 switch through br-int
Cross-node: Geneve tunnel (L3 overlay)
Provides connectivity. Pods can talk to each other.
ztunnel (ambient mesh layer)
DaemonSet per node, same pattern as OVN-K
Intercept: iptables REDIRECT :15001
Cross-node: HBONE tunnel (mTLS overlay)
Adds encryption and identity on top of OVN-K.
routingViaHost: true is the seam — it forces OVN-K to route through the host kernel where ztunnel's iptables rules can intercept.

      5
      Zero Trust Security
    

    

      

        Two layers of zero trust. Layer 1: PeerAuthentication (ztunnel, L4) controls whether
        non-mesh traffic is allowed at all. Layer 2: AuthorizationPolicy (waypoint, L7) controls
        which mesh identities can reach which services.
      


      

        
Layer 1: PeerAuthentication

        

          Enforced by ztunnel (L4). Controls whether pods accept connections without a valid mTLS certificate.
          STRICT = mesh identity required. PERMISSIVE = plaintext allowed.

          Enforced by waypoint (L7). Controls which SPIFFE identities can reach which services.
